结论：修复本轮发现的交付阻碍后，可以作为源码包交付试用。全部验证使用合成数据；这不是学校端到端运行保证。

| 已复现问题 | 最终处理 |
|---|---|
| 迟到/时钟回拨的快照被直接丢弃 | 原文入持久历史并标 observed_late；不覆盖较新版本；异常实时采集不报完整 |
| 日历超过50条、后页失败、帖子数量不符时丢弃已取正文 | 日历完整分页；保留部分结果，错误状态仍明确 |

| 作业/测验 intro/activity 附件与链接正文绕过核读 | 全部内容入口显式待核读，缺媒体核读依据不能确认 |
| 图片/附件变化后考试仍显示已核读 | 来源哈希覆盖原始图文、附件元数据 |
| 损坏快照/数据库失败后考试仍显示已核读 | 失败统一标待核读，保留原文件；初始化失败释放数据库句柄 |
| 全局课程摘要与分页顺序不同 | 共用排序，预算裁剪后的课程可完整恢复 |
| Windows junction 使打包带入外部文件 | 遍历前检查各级路径，不跟随链接；保留正常学习工具源码 |

所有已复现的上述缺陷均有回归用例。未观察到仍阻碍本次源码交付的失败。

## Token 口径

使用 tiktoken 0.12.0 的 o200k_base 和 cl100k_base 对实际本地输出文本分词。无付费模型调用。不是字符数除以四，也不是账号计费测量。

课程场景：原版整份状态与按课程读取对比；新版本包含全部课程索引分页、教学必读字段和相关错题/教师结论原文。8 门课样本真实走 list 恢复省略条目，没有使用事先知道的隐藏编号。原版若也采用同样的精准读取，差距会小很多。

下表为 o200k_base。原版整份状态已去掉 JSON 缩进，采用较保守的对照。

| 场景 | 原版对照文本 Token | 修复后 Token | 减少 |
|---|---:|---:|---:|
| 3门课档案，读其中一课 | 8,617 | 1,808 | 79.0% |
| 5门课档案，读其中一课 | 35,611 | 3,361 | 90.6% |
| 8门课档案，读其中一课 | 108,004 | 5,766 | 94.7% |
| 首次同步+9次无变化通知检查 | 31,100 | 11,148 | 64.2% |
| 同样的计划与复习题，含完整本地输出 | 972 | 613 | 36.9% |

通知样本包含5门课、40条虚构教师帖子，共55个来源记录。首次同步为3,110 → 10,041 Token：逐版本核读与回执确实增加开销，不隐藏这个结果。随后无变化为3,110 → 123；单条教师正文修改为3,099 → 352。十轮数字是首次一次加九次同类检查的输出合计，不是十轮真实模型会话。

未计入模型回答、推理、工具参数/定义、系统提示、历史重放/缓存和图片附件。测试中的“已核读”是基于虚构正文的测试回执；没有声称真实学生已读通知。不能据此承诺 Plus 多用多少倍。

## 复现

在项目自己的 Python 环境按需安装 tiktoken==0.12.0，再运行：

    .venv/Scripts/python.exe tools/release/benchmark_tokens.py

生产功能不需要 tiktoken。计量工具只生成合成数据，在 .local/token-benchmark-v2/ 保存每个流程输出与 results.json，不读取真实 Study/。首次使用分词器可能下载公共词表。

源码包使用 package-source.ps1 白名单打包，排除 Study/、登录凭据、本地配置、依赖、开发备份和测量缓存。安装后每个同学自己登录并选择课程。
